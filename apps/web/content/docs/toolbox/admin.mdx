**Answerable staff.** This page is for us. Every step is a `curl` command. The Toolbox itself is described in [The Toolbox](/docs/toolbox). [Set up the admin MCP](/docs/admin/setup) registers the admin MCP's machine client for the Toolbox's admin resource.

## Enable an organisation

In [the admin MCP](/docs/admin), ask for it in words, as [the two steps for each organisation](/docs/mcp/sign-in#what-staff-do-for-each-organisation) show:

```text
Enable the Toolbox for Newco with provider e2e, from claude-code-toolbox.
```

`toolbox_enable` previews every row it would make, then, once you confirm, makes them in Answerable ID with the admin MCP's own machine client and enables the providers in the organisation's catalogue through this API. The Toolbox writes nothing to ID itself, since every MCP's code shares its process ([What MCPs share](/docs/toolbox#what-mcps-share)). Locally, `bun mcp dev <name>` makes the same rows for your organisation, from the same plan, as `mcp-dev`.

## What enabling makes

**Reads first, then writes.** Prepare reads what ID holds and stops on a row that does not fit; the preview lists exactly what the commit makes, in this order:

| Step | What it makes | Skipped when |
| --- | --- | --- |
| 1. Link | For each host client, links it to the Toolbox resource | The resource already lists the client |
| 2. Capabilities | For each host client and both grant kinds (`authorization_code`, `refresh_token`): the organisation's login capability (`openid offline_access`, no resource) and its `toolbox` capability for the Toolbox resource | An active row for that client, resource and grant kind carries those scopes |
| 3. Entitlements | For each host client: an organisation-wide login entitlement and `toolbox` entitlement | An active organisation-wide row for that client and resource carries those scopes |
| 4. Catalogue | Enables each named provider for the organisation, through `PUT` of its catalogue entry. An entry that exists keeps its overrides | The provider is already enabled |

**The grant strings come first.** The Toolbox resource must already allow every grant string of the named providers. The register Job of the deploy that ships a provider allows them, once the servers have rolled; until it has run, `toolbox_enable` answers `PRECONDITION_FAILED` naming the scopes the resource lacks.

**Retries.** A row that exists with another status or too few scopes stops the preparation with `PRECONDITION_FAILED`, naming the row; fix it in ID and prepare again. Each write carries the intent's key and its place, so a commit retried replays. Nothing is rolled back: if ID or the Toolbox fails part-way, prepare and commit the same request again, and it makes only what is missing.

**Grant strings for people are not written.** Enabling makes the token possible; who may use which capability is the organisation's decision. See [Grant strings for people](#grant-strings-for-people).

## Register the Toolbox in ID

Locally, `bun mcp setup`, then `bun mcp dev <name>`: [Run an MCP on your machine](/docs/mcp/run-locally). In a deployment, the register Job: [Set up the admin MCP](/docs/admin/setup). Both register, field for field:

| Row | What it is |
| --- | --- |
| The Toolbox resource, `<origin>/mcp` | Its audience, which must match `TOOLBOX_RESOURCE_URL` exactly. It allows `toolbox`, `offline_access`, `toolbox/approve` and every grant string of the MCPs its hub serves, from their manifests, and 900-second tokens. The register Job reads them from `infra/ops/src/toolbox-scopes.generated.ts`, which `bun mcp` writes; `bun mcp dev` from the repository |
| The admin resource, `<origin>/admin` | What guards this API: `toolbox:admin`, 300-second tokens. Its identifier is the origin of `TOOLBOX_RESOURCE_URL` and `/admin`; there is no variable for it |
| The host client `claude-code-toolbox` | A public client for a person's app, with `toolbox` among its scopes |
| A machine client on ID's admin API | What the Toolbox reads grants and who is calling with, with `platform:read`; it writes nothing to ID: `toolbox-hub` in a deployment, `mcp-dev` locally |
| A machine client with `toolbox:admin` on the admin resource | What calls this API: `admin-mcp` in a deployment, `mcp-dev` locally. A person's token is refused |

Do not link the host client or add its capabilities and entitlements by hand: `toolbox_enable` does. Until it first names the client, the client is not linked to the Toolbox, so a person signing in through it gets `invalid_target` from ID instead of the organisation chooser's "Access is unavailable for this organisation".

## The catalogue

The catalogue is the ceiling for an organisation: what it may use at all, whatever its entitlements say. Get a token for the admin resource, list what can be enabled, then set an organisation's entry:

```bash
export ID=http://localhost:47300
export TOOLBOX=http://localhost:47400
export ORG=0199a0d1-0000-7000-8000-000000000000   # the organisation's id in ID

# A token for the Toolbox's admin resource, as a machine client with toolbox:admin: locally mcp-dev, from the root .env
TOOLBOX_TOKEN=$(curl -s "$ID/auth/oauth2/token" --user "$MCP_DEV_ID_CLIENT_ID:$MCP_DEV_ID_CLIENT_SECRET" \
  --data-urlencode grant_type=client_credentials \
  --data-urlencode resource="$TOOLBOX/admin" \
  --data-urlencode scope=toolbox:admin | jq -r .access_token)

curl "$TOOLBOX/admin/v1/providers" -H "Authorization: Bearer $TOOLBOX_TOKEN"

curl -X PUT "$TOOLBOX/admin/v1/organisations/$ORG/catalogue/e2e" \
  -H "Authorization: Bearer $TOOLBOX_TOKEN" -H "Content-Type: application/json" \
  -d '{"enabled":true,"overrides":{"disabled":["e2e/records.list"],"policy_class":{"e2e/records.delete":"human"}}}'

curl "$TOOLBOX/admin/v1/organisations/$ORG/catalogue" -H "Authorization: Bearer $TOOLBOX_TOKEN"
```

- **`GET /providers`** lists each mounted provider with its version and capabilities (`identity`, `version`, `kind`, `risk`, `title`). The Toolbox's own provider, `toolbox`, is always on and not listed.
- **`PUT` replaces the entry.** Fields you leave out go back to their defaults: no `overrides` means none. Repeating a `PUT` changes nothing.
- **Disable a capability** by listing its identity in `overrides.disabled`. It disappears from that organisation's `tools/list` on the next request, and a call to it answers the unknown-tool error. In the acceptance, `e2e_records_list` was hidden from a member 4 to 14 ms after the call, in eight runs. A host that keeps `tools/list` for its 30-second hint lists the change up to 30 seconds later.
- **Set a policy class** with `overrides.policy_class`, mapping a mutation's identity to `agent`, `controlled` or `human`. It replaces the class its `risk` gives. A read is refused with `422 not_a_mutation`.
- **New capabilities stay off until enabled.** When a provider version adds a capability the provider never had, its identity is appended to `overrides.disabled` of every organisation that has the provider enabled, when the Toolbox boots. `GET` the catalogue to see them; a `PUT` that leaves them out of `disabled` enables them. Organisations that have the provider disabled are not touched, and neither is a capability that only changed version.

## Host clients

```bash
curl -X PUT "$TOOLBOX/admin/v1/host-clients/claude-code-toolbox" \
  -H "Authorization: Bearer $TOOLBOX_TOKEN" -H "Content-Type: application/json" \
  -d '{"projection":"meta","direct_limit":40}'
curl "$TOOLBOX/admin/v1/host-clients" -H "Authorization: Bearer $TOOLBOX_TOKEN"
curl -X DELETE "$TOOLBOX/admin/v1/host-clients/claude-code-toolbox" -H "Authorization: Bearer $TOOLBOX_TOKEN"
```

A row is keyed by the host's OAuth client id (percent-encode one that is a URL). A client without a row gets the defaults.

| Field | Values | Default |
| --- | --- | --- |
| `projection` | `direct` (one tool per granted capability), `meta` (search, describe, execute, prepare and commit tools), `auto` (direct until the person's set exceeds `direct_limit`) | `auto` |
| `direct_limit` | 1 to 128, the most tools a person is given directly under `auto` | 40 |

**Which hosts need `meta`.** A host that caps the tools in a request needs it: VS Code Copilot caps a request at 128. Hosts that govern by tool name, such as Claude Code's approvals and Claude.ai's per-tool controls, need the direct list where it fits, so leave them on `auto`.

The Toolbox reads the row on every request that lists or calls tools: `auto` serves the direct list while the caller's granted tools number at most `direct_limit`, else the [meta projection](/docs/toolbox#the-meta-projection). A change applies to the host's next request. Pins: Not yet.

## Grant strings for people

Enabling lets a host client get a token for the organisation. What each person may use is an entitlement to the Toolbox resource whose `scopes` are [grant strings](/docs/toolbox#grant-strings): a provider (`e2e`), a domain (`e2e/records`) or a capability (`e2e/records.list`). Use [ID's entitlement API](/docs/id/admin-api/entitlements/createEntitlement), with `TOKEN` a [staff token for ID](/docs/id/onboard#get-a-staff-token); the organisation, one group or one member can hold one:

```bash
export MCP=$TOOLBOX/mcp

# Everyone in the organisation: every capability of the e2e provider
curl "$ID/api/admin/v1/organizations/$ORG/entitlements" -H "Idempotency-Key: e2e-organisation-v1" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"resource":"'"$MCP"'","scopes":["e2e"]}'

# One group: the records domain
curl "$ID/api/admin/v1/organizations/$ORG/entitlements" -H "Idempotency-Key: e2e-group-v1" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"groupId":"'"$GROUP"'","resource":"'"$MCP"'","scopes":["e2e/records"]}'

# One member: one capability
curl "$ID/api/admin/v1/organizations/$ORG/entitlements" -H "Idempotency-Key: e2e-member-v1" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"memberId":"'"$MEMBER"'","resource":"'"$MCP"'","scopes":["e2e/records.list"]}'
```

Rows are additive and there is no deny. ID refuses a scope the resource does not allow; the register Job of the deploy that ships a provider allows its grant strings. A change reaches the person within 60 seconds. Until organisation administrators can do this themselves, staff do: tenant-tier writes are Not yet. Through [the admin MCP](/docs/admin#some-tools-not-all), `access_grant` makes the same entitlement with a preview and a receipt.

## Check evidence

```bash
curl "$TOOLBOX/admin/v1/organisations/$ORG/evidence/verify" -H "Authorization: Bearer $TOOLBOX_TOKEN"
```

```json
{ "ok": true, "length": 2 }
```

It recomputes the organisation's evidence chain, as [The Toolbox](/docs/toolbox#evidence) describes. A broken chain answers `200` with `"ok": false` and `broken_at`, the first `seq` that fails.

## Routes

Every route lives under `/admin/v1`, takes and answers JSON, and needs `Authorization: Bearer` with a machine client's token for the admin resource carrying `toolbox:admin`. Organisation ids are UUIDs.

| Route | Does | Answers |
| --- | --- | --- |
| `GET /providers` | Lists the mounted providers and their capabilities | `200 { items }` |
| `GET /organisations/{organisationId}/catalogue` | Lists the organisation's entries: per provider `provider_id`, `enabled` and `overrides` | `200 { items }` |
| `PUT /organisations/{organisationId}/catalogue/{providerId}` | Replaces the entry: `{ enabled, overrides?: { disabled?, policy_class? } }` | `200` the entry |
| `GET /host-clients` | Lists the host client rows | `200 { items }` |
| `PUT /host-clients/{clientId}` | Replaces the row: `{ projection?, direct_limit? }` | `200` the row |
| `DELETE /host-clients/{clientId}` | Removes the row | `204` |
| `GET /organisations/{organisationId}/evidence/verify` | Checks the chain | `200 { ok, length, broken_at? }` |

A body may carry only the fields listed; an unknown field answers `400`. Responses carry `Cache-Control: no-store`.

## Limits

| Limit | Value |
| --- | --- |
| Who may call | Machine clients with `toolbox:admin`. A person's token, another audience or another scope is refused |
| Self-service purchase, and administration by an organisation's own administrators (tenant-tier writes) | Not yet |
| OpenAPI description of this API | Not yet; the routes table above is the contract |
| Evidence of admin calls | Not yet. `toolbox_enable` is evidence in the admin MCP, and the rows it makes are in ID's audit log, as the admin MCP's machine client |
| Rows `toolbox_enable` reads | By status and scopes; validity windows are not read |
| Organisation ids | The routes do not check an organisation against ID; `toolbox_enable` does |
| Atomicity | `toolbox_enable` is not atomic: a failure leaves what it made, and preparing and committing again finishes it |
| ID unavailable | The routes need the Toolbox's database, and ID only once, to fetch its signing keys |
| Host client settings | Read on every request; a change reaches a `2026-07-28` host after its 30-second `tools/list` cache |

## Errors

Every failure answers `{ "error": { "code": "...", "message": "..." } }`; the message says what to change. A `401` carries `WWW-Authenticate: Bearer realm="toolbox-admin"`, and a `403` carries `error="insufficient_scope"`.

| Status and code | Meaning | What to do |
| --- | --- | --- |
| `401 unauthorized` | No bearer token, or one that is invalid, expired, for another audience or a person's | Request a token from ID with `resource` set to the admin resource and `scope=toolbox:admin`, as a machine client that holds it |
| `403 forbidden` | The token lacks `toolbox:admin` | Locally, run `bun mcp setup` again, which gives `mcp-dev` the scope; in a deployment, the register Job gives it to `admin-mcp` |
| `400 invalid_request` | The body is not JSON, has a field of the wrong type, a field the route does not take, an organisation id that is not a UUID, or a path that is not valid percent-encoding | Fix what the message names |
| `404 not_found` | No such route | Check the method and path against [Routes](#routes) |
| `404 provider_not_found` | The provider is not mounted in this Toolbox | `GET /providers` lists them |
| `404 host_client_not_found` | No row for that client id | `GET /host-clients` lists them |
| `422 unknown_capability` | `overrides` names an identity the provider does not have | Use identities from `GET /providers` |
| `422 not_a_mutation` | `policy_class` names a read | Set a policy class only for mutations |
| `500 internal_error` | Something unexpected, such as the database | The Toolbox's log has `[toolbox] admin API failed` |

The Toolbox journeys in `packages/acceptance` enable organisations from the same plan against real ID, and the admin journeys through `toolbox_enable`: [What the acceptance proves](/docs/mcp/local-testing#what-the-acceptance-proves).
